\section{Executive Summary}

We explored random forest classifiers, naive Bayes classifiers, and multinomial logistic regression models. Our best-performing model was a random forest classifier, with a projected accuracy of 76.4\%. The random forest's ability to model complex, likely nonlinear relationships between a mix of categorial and text features makes it suitable for this task.

\section{Data Exploration} 

\subsection{Summary of dataset}
Each of 275 students contributed one data point for each class label (ChatGPT, Claude, Gemini), resulting in a perfectly balanced 3-class dataset. The features include:

\textbf{4 numerical features}: likelihood of academic use, frequency of suboptimal responses, frequency of references, frequency of user verification.

\textbf{2 categorical features}: most suitable tasks, least suitable tasks.

\textbf{3 text features}: most suitable tasks, least suitable task with explanation, method of user verification.

The distribution of each of numerical feature is shown in \Cref{fig:feature-distributions}. As expected, the mean and median are generally close to the neutral answer 3, although the mode is 4 for the first and last questions.

\subsection{Data issues}
\begin{itemize}
  \item The dataset is missing at least 118 values, e.g.~student\_id = 3. Missing numerical features were imputed as 3 (neutral); see \texttt{build\_features} in \texttt{preprocessing.py}.
  \item Two data points (student\_id = 2 and 15) contained a nonsensical feature ``\#NAME?''. These were removed prior to training to prevent the model from learning from it.
\end{itemize}

\subsection{Preprocessing}
\begin{itemize}
  \item To preserve ordinal information, Likert-scale features were converted to numerical by extracting the first character using regex pattern matching; see 
  \texttt{extract\_rating} in \texttt{preprocessing.py}.
  \item Multi-select survey responses were converted into binary indicator features using MultiLabelBinarizer; see \texttt{build\_features} in \texttt{preprocessing.py}.
  \item For logistic regression, the text data in the dataset was preprocessed by applying TF-IDF
  vectorization to each free-text column, converting the raw text into numerical
  features that capture the importance of each word relative to the whole; see \texttt{preprocessing\_tfidf.py}.
  \item For the random forest classifier, a bag of words representation was implemented in \texttt{random\_forest.ipynb}.
\end{itemize}

\subsection{Data Splitting}
\begin{itemize}
  \item data-split.py groups the cleaned dataset by student\_id and randomly splits 85/15 for training/test. The file training.csv was used for training and hyperparameter tuning; test.csv was only used to measure final model performance.
\end{itemize}

\subsection{Logistic Regression}
Logistic (softmax) regression is a stable and efficient classifier for simple datasets such as this. It readily affords further techniques such as feature mapping to capture nonlinear relationships and regularization to prevent overfitting our small training set. We tuned a logistic regression model both including and excluding text features represented by TF-IDF, but observed that including TF-IDF features improved validation performance at the cost of higher variance between folds.

\textbf{Optimization:} For training, we used the built-in optimizers in the \texttt{LogisticRegression} class from scikit-learn. We chose the \texttt{lbfgs} solver for L2 regularization and \texttt{saga} solver for L1 regularization. We set \texttt{max\_iter=5000} to ensure convergence when tuning hyperparameters, but used \texttt{max\_iter=1000} for final testing to meet the computational requirements.

\textbf{Hyperparameters:}
The optimal combination of hyperparameters was selected by a grid search; see \texttt{log\_reg\_tuning} and \texttt{log\_reg\_tfidf\_tuning}. The search range for each hyperparameter is justified below.
\begin{itemize}
    \item \texttt{max\_features}: the maximum number of tokens considered in the TF-IDF representation of text features. We searched over the range $\{100, 300, 500, 1000\}$, and validation results (see \Cref{fig:log-reg-hyperparams}) showed that accuracy, precision, recall, and F1 score are all maximized at \texttt{max\_features} $= 300$, providing evidence that this range is reasonable for our dataset.
    \item \texttt{n-gram range}. Allows the TF-IDF representation to consider short phrase combinations, rather than just individual words. We tried introducing bigrams (two word combinations), searching over the range \texttt{n-gram range} $ \in \{(1,1), (1,2)\}$. However we noticed immediate overfitting as $n$ increased as the mean training accuracy was 0.993 and the mean validation accuracy was 0.674 for $(1,2)$, as opposed to mean training accuracy 0.854 and mean validation accuracy 0.688 for $(1,1)$.
    \item \textbf{Regularization strength:} $C \in \{0.1, 0.5, 1, 5, 10\}$, controlling the inverse of regularization. From \Cref{fig:log-reg-hyperparams}, we observe the trend of slightly underfitting when $C$ is too small, thus regularization is too strong, and overfitting when $C$ is too large.
    \item \textbf{Penalty:} We experimented with both L1 and L2 regularization. 
    L2 regularization encourages smaller coefficients and generally yields
    stable models, while L1 can produce sparse coefficients, potentially useful
    if some features are irrelevant. We could have also tried elasticnet which combines L1 and L2, but we found that L2 significantly outperformed L1.
    \item \textbf{Solver:} We used \texttt{lbfgs} for L2 regularization and
    \texttt{saga} for L1 regularization, as recommended by the
    \texttt{scikit-learn} documentation~\cite{sklearn_logreg}.
\end{itemize}

\subsection{Naive Bayes Classifier}
Naive Bayes is well-suited for our dataset because most survey features are discrete, low-cardinality variables such as Likert-scale responses and binary indicators. The naive Bayes assumption may not be perfectly true, for example the numerical features regarding likelihood of academic use and frequency of suboptimal responses are plausibly correlated. However, it seems reasonable to assume that features are approximately conditionally independent given class, hence a naive Bayes classifier can be very effective.

\textbf{Optimization:} Naive Bayes does not require iterative optimization. Parameters have closed-form maximum-likelihood estimates derived from empirical counts (categorical features) or means/variances (numerical features).

\textbf{Hyperparameters:} We tuned the Laplace smoothing coefficient $\alpha$, which addresses the zero-probability problem in Bayesian classifiers by adding a small constant $\alpha$ to each feature count. The search range for $\alpha$, namely $\alpha \in \{0.01,0.1,0.5,1.0,2.0,5.0,10.0\}$, was chosen following the recommendation of Manning, Raghavan, and Sch\"utze~\cite{Manning_Raghavan_Schütze_2008}. The effect of $\alpha$ on the evaluation metrics is shown in \Cref{fig:nb-alpha}.

\subsection{Random Forest Classifier}
Decision trees are suitable for mixed feature types and capturing relationships between numerical features and binary categorical features, which form an important part of our dataset. The numerical features exhibit relatively concentrated distributions, with the most concentration near rating 3 to 4. This means sampled values are more predictable, and Gini impurity from numerical feature splits can be quite informative. We can extend this to random forests, using ensemble averaging to avoid overfitting.

\textbf{Optimization:} We used the Gini impurity criterion for sklearn's \texttt{RandomForestClassifier} class, which measures how mixed the class labels are. Since the hyperparameters do not interact, it is not necessary to perform a grid search; it suffices to tune each hyperparameter separately.

\textbf{Hyperparameters:} See \texttt{random\_forest.ipynb} for implementation details.
\begin{itemize}
  \item \texttt{vocab\_size}: the number of words considered in the bag of words representation of text features. The search range 
  \[\{1, 10, 50, 100, 500, 1000, 1500, 2000, 2500, 3000, 3500, 4000, 4500, 5000, 5687\}\]
  ranges from a single word to the total number of distinct words in the dataset, $5687$.
  
  \item \texttt{n\_estimators}: the number of trees in the random forest. \texttt{range}$(1, 1000, 10)$ covers a very broad range, and the validation results (see \Cref{fig:rf-hyperparams}) shows a visible initial learning curve and eventual smoothing, justifying this search range.
  
  \item \texttt{max\_depth}: the maximum depth of a tree in the random forest. Again, the search range was \texttt{range}$(1, 1000, 10)$, and is justified by the initially steep learning rate and almost immediate smoothing.
  \item \texttt{max\_features}: the maximum number of features considered at each split in a tree. We searched among 'sqrt', 'log2', 0.2, 0.5, 1.0, but the validation accuracy for 'sqrt' was by far the highest.
  \item \texttt{min\_samples}: the minimum number of samples required to be a leaf node. In the search range $\{1, 2, 5, 10, 20, 50\}$, \texttt{min\_samples} $=1$ attained the highest validation accuracy by a large margin.
\end{itemize}

\subsection{Validation}
We employed grouped 5-fold cross-validation using \texttt{GroupKFold}, grouping by \texttt{student\_id} to avoid data leakage across folds (see \texttt{logistic\_regression\_tfidf.py}) as well as hold-out validation with a 70/15/15 split for training/validation/test.

\subsection{Evaluation}
We evaluated our models using accuracy, precision, recall, and F1. The final decision was heavily based on accuracy and F1, which combines precision and recall.

\subsection{Naive Bayes Classifier}
The optimal Laplace smoothing coefficient was $\alpha = 5.0$. The test performance of this model is summarized in \Cref{tab:model_metrics}.

\textbf{Error Analysis:} From the confusion matrix, we see that the naive Bayes classifier identified ChatGPT with high recall (0.875), but lower precision (0.648). It suffered with low recall (0.382) for Gemini, which it confused the most with Claude but also significantly with ChatGPT. It demonstrated balanced but mediocre precision (0.529) and recall (0.546) for Claude. This suggests that the naive Bayes classifier suffer from many false positives for ChatGPT and many false negatives for Gemini.
